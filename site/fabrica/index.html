Estado, revisiones humanas y Git.

La operas por CLI o TUI en tu máquina. Este sitio explica el producto; la operación ocurre en tu terminal.

  1. Workstream

    Define un objetivo, un repositorio, el agente y las aprobaciones requeridas.

  2. Signal

    Registra una entrada manual o importa un issue de Jira con su contexto.

  3. Change

    Promueve la señal a una propuesta de cambio. Espera tu aprobación por defecto antes de investigar; se desactiva con --no-change-approval.

  4. Activity

    El pool asigna investigación e implementación a workers. La revisión de la especificación viene activa por defecto; se desactiva con --no-spec-approval.

La integración tiene su puerta.

Cada change usa una rama y un worktree. Si solicitas validadores, los pendientes o en FAIL bloquean fab merge. El override explícito --force permite omitir ese bloqueo.

El merge integra en la rama actual del repositorio y retira el worktree del change.

Explorar la puerta de merge

Funciones clave del ciclo de fábrica

Entrada de trabajo

Define el objetivo y el repositorio del workstream con fab ws create.

Registra una señal manual o importa un issue de Jira con su contexto completo.

Promueve explícitamente las señales que decidas convertir en changes.

Revisiones humanas

Revisión de change y especificación activas por defecto; desactivables con flags.

Consulta las actividades que esperan decisión en la bandeja de entrada.

Aprueba, comenta o rechaza la propuesta antes de que avance.

Ejecución y ramas Git

Selecciona el agente (nativo o adaptadores externos) que ejecutará las tareas.

Ajusta la concurrencia y el límite de tareas del pool de workers.

Investigación e implementación trabajan en el worktree aislado del change.

Validación y PR

Solicita suites independientes de revisión de código, seguridad y QA.

Consulta y publica resultados estructurados con veredictos PASS o FAIL.

Abre y consulta el pull request del change con validación previa.

Puerta de merge

El change debe haber completado la implementación en su rama propia.

Validadores pendientes o con veredicto FAIL bloquean la integración.

El modificador --force permite omitir el bloqueo cuando sea necesario.

Seguimiento y recuperación

Abre la vista completa de changes, bandeja y eventos con fab tui <slug>.

Supervisa el estado y detalle de cada propuesta desde comandos dedicados.

Reencola actividades fallidas o cancela propuestas retirando worktrees.

Comandos de seguimiento y recuperación

Seguimiento y recuperación

Supervisa el avance de la fábrica, revisa el registro histórico e interviene con comandos directos de inspección y recuperación.

fab status [slug]

Muestra el estado del workstream, la lista de changes y su última actividad en curso.

fab show <id>

Inspecciona el detalle del change, su rama Git asociada y el resultado o error de cada actividad.

fab events [slug] [--limit N]

Consulta el registro cronológico de eventos con su marca de tiempo, severidad y mensaje.

fab inbox

Lista las actividades pendientes de revisión humana para su aprobación o comentario.

fab retry <change-id>

Reencola una actividad fallida para que el pool de workers vuelva a procesarla.

fab reject <change-id> [--reason texto]

Cancela una propuesta de cambio y retira de forma limpia su worktree de Git.

Terminal de seguimiento 
$ fab status mi-objetivo
mi-objetivo [active] agent=native — Migrar endpoints a v2
  951e7eb3 implemented  Añadir endpoints v2  [qa:done/fail]

$ fab inbox
  951e7eb3 investigation  Esperando aprobación de especificación

$ fab retry 951e7eb3
change 951e7eb3: qa re-encolada

$ fab reject 951e7eb3 --reason "superado por refactor"
change 951e7eb3 cancelado; worktree retirado

Estado local, conexiones explícitas.

La base técnica vive en tu máquina y repositorio: CLI y TUI para cada propósito, persistencia local y diagnóstico de sistema.

CLI y paneles dedicados

fab o fab <carpeta> para el agente conversacional, fab exec para tareas sin interfaz y fab tui <slug> para el panel operativo del workstream.

Diagnóstico y acceso a modelos

fab doctor informa del estado del sandbox, Script y búsqueda. Conecta con el router auto (clasificador heurístico o Jev opcional de TypeSafe con clave y relativeCost) y router omni por cuenta y cuota operacional (costTier).

El estado y el código, en su sitio.

SQLite local (~/.fabrica/fabrica.db, configurable con FABRICA_HOME) conserva el flujo de la fábrica. Git conserva los cambios en los worktrees y ramas de tu repositorio. El pool lanza un agente para ejecutar cada actividad.

El ciclo de la fábrica y el runtime del agente

La fábrica organiza el flujo con estado persistente en SQLite; el agente ejecuta la actividad en un worktree independiente de Git.

Importación, aprobaciones humanas, workers y puerta de merge. El override explícito --force existe.

De tu terminal al trabajo.

  1. Define tu objetivo

    fab ws create mi-objetivo --repo . --goal "Migrar endpoints a v2"

  2. Activa el workstream

    fab ws state mi-objetivo active

  3. Ejecuta el pool

    fab run

  4. Consulta el estado

    fab status mi-objetivo
